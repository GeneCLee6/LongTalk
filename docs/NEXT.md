- **2026-11-02 修正：三人以上的房間有人的鏡頭收不到**（#13，bug fix，不屬於任何批次）：C1 截圖時發現同一房第 3 人以後常有人只剩聲音、出現「媒體伺服器回應錯誤」。用 3–5 個 headless Chrome（假裝置）在正式站與 PR 預覽重現，記下每個 `/api/sfu` 呼叫、送給房間的 `tracks`、PeerConnection 狀態與 SDP。**主因**（Playwright 的 headless Chromium 每次都中）：第三人先 pull 了兩個人的鏡頭、再 push 自己的鏡頭時，Chrome 給新的 video m-section 重新編 payload type（H264 用 97、VP9 的 RTX 用 99），SFU 的 answer 卻沿用它先前 offer 裡的編號（H264 125、RTX 36），也就是 offer 裡沒有的編號，瀏覽器拒絕套用（`Failed to set remote video description send parameters for m-section with mid='5'`）；push 已回 200，舊版把 offer 收回、顯示錯誤、從不重試，鏡頭就從沒告訴房間，SFU 與瀏覽器的 SDP 也從此不一致（之後的 406）。**其他原因**：(1) 發布端 push 一回 200 就把軌告訴房間，但 PeerConnection 可能還沒送出封包（甚至沒連上），其他人 pull 時 SFU 卡約 8 秒再回 `empty_track_error`，卡住期間訂閱端自己的 push 也排在後面；(2) `RoomMedia` 對失敗的訂閱只重試 3 次就永遠放棄；(3) 發布失敗從不重試；(4) pull 回應頂層有錯但仍帶 SFU 的 offer、或 SDP 交換做到一半失敗時，session 卡在等 answer 卻不會重建。修法：`CloudflareRealtimeTransport` 送出的視訊只提供 VP8（`setCodecPreferences`），等 sender 真的送出封包才回傳發布結果（10 秒沒有就當連線壞了、重建），只要回應帶 offer 就先回答，pull 的 mid 從該軌的結果讀，SDP 交換半途失敗或 406 就讓 transport `failed` 由 `RoomMedia` 重建；`RoomMedia` 訂閱與發布失敗改成退避重試（2、4、8 秒，最多每 15 秒一次，軌還在清單上就不放棄；發布者重新回報該軌時立即重試）。通訊協定不變。測試：`tests/app/media/realtimeRaces.test.ts` 用照 Realtime 規則行事的假 SFU（重疊或等 answer 時回 406、還沒封包的軌回 `empty_track_error`）重現並行 pull／push、pull 先於發布完成、立即重新協商穿插、三到四人錯開加入；e2e 改成**三人每隔 3 秒加入、每人都要看到並聽到另外兩人**，並在 log 印出每人的 `/api/sfu` 呼叫、`tracks`、PeerConnection 狀態與 `getUserMedia` 失敗（`DEPLOY.md` §7）。Realtime 協商規則補在 ADR-001。**還會偶爾失敗的**：Chrome 的假鏡頭偶爾整個不見（`getUserMedia` 回 `NotFoundError`，畫面「找不到鏡頭」），是測試環境的問題，CI 重試 1 次吸收。

## 3. 工作方式（每批）

1. **在 worktree 開分支**：`git worktree add ../_wt/<分支> -b feat/<第一個 task 編號>-<slug>`。
2. **只讀需要的段落**：`CLAUDE.md`、這份、`ROADMAP.md` 的該批、該批 task 所在的 epic 段落、相關的 `ARCHITECTURE.md` 章節。不要整本讀。
3. **做完跑** `npm run lint && npm run typecheck && npm test && npm run build`，只看最後 5 行。
4. **一批一個 ready PR**：標題英文、結尾列出全部 task 編號；本文（繁中）寫對應 AC、怎麼驗證、兩台裝置實測結果（媒體相關）。
5. **在同一個 PR 更新文件**：epic 勾選 task（寫 PR 號）、AC 勾選（有驗證才勾）、`PRD/README.md` 進度表、`ROADMAP.md` 該批 `[x]` 與 PR 號、這份「現在的位置」。
6. **CI 綠了直接合併**（`gh pr merge --squash --delete-branch`），需要人決定的事才停下來問。
7. 合併後回報：做了什麼、PR 號、下一批是哪一批、有沒有等人決定的事。
