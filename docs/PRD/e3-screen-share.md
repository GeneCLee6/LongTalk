## 背景

螢幕分享是使用者點名的三個核心之一（麥克風、視訊、分享）。瀏覽器的 `getDisplayMedia()` 已經能選螢幕／視窗／分頁，Chrome 系還能帶分頁音訊或系統音訊；Safari 能分享但沒有音訊；iOS 瀏覽器完全不能分享。所以 E3 的重點不是「能不能」，而是：分享畫面看得清楚（文字模式）、分享中大家都知道、停止不會卡住、版面自動切換，以及把每個瀏覽器的能力差異處理好。

M2 的畫筆標註（E7）疊在分享畫面上，所以 E3 要在 M0 就把「分享畫面的實際顯示矩形」當成可以查詢的狀態。

## 目標

- M0：一人分享螢幕／視窗／分頁，含分頁音訊（支援時）；全員版面切成「分享為主」；分享中有明顯提示；停止分享（含瀏覽器原生的停止按鈕）正確收尾。
- M1：文字／動態兩種模式；多人同時分享與切換觀看；分享者看得到縮圖（簡報者檢視）；手機不支援時的說明。
- M2：分享畫面全螢幕與縮放；標註對齊用的座標 API 給 E7。

## 非目標

- 分享畫面的錄影（E8）、標註本身（E7）、遠端控制（E9）。
- 分享 iOS 螢幕（瀏覽器做不到）。

## 需求

### 功能

- 分享來源：由瀏覽器的選擇器決定；`preferCurrentTab: false`、`selfBrowserSurface: 'exclude'`（避免分享自己的會議分頁）、`surfaceSwitching: 'include'`。
- 音訊：`audio: true`，Chrome 分頁分享帶分頁音訊、整個螢幕可帶系統音訊；分享音訊作為獨立軌 `screenAudio`，接收端混進喇叭輸出，分享者可在工具列關掉。
- 狀態：RoomDO 記錄 `screen` 軌屬於誰；M0 一次一人，第二人按分享會先問「接手分享？」；M1（H5）起最多 3 人同時分享（`MAX_SHARES`），不再問接手，由觀看者選擇主區看誰，第四人按分享看到「已經有 3 個人在分享畫面」。
- 提示：分享者的畫面頂端有「你正在分享」條與停止按鈕；其他人的分享格有「<名字> 的畫面」標籤。
- 停止：工具列、提示條、瀏覽器原生停止按鈕（監聽 `track.onended`）三條路都要正確 unpublish 並恢復版面。
- 模式（M1）：「文字」＝ `contentHint: 'detail'`、解析度優先（最高 1080p，`balanced`，最高 30 fps：D1 實測 15 fps 捲動會卡，壓力下幀率先掉）；「動態」＝ `contentHint: 'motion'`、幀率優先（`maintain-framerate`，30 fps，最高 720p）；預設文字，分享畫面持續在動時提示切換（H5 的量測在 ADR-001「分享模式與多人分享」）。
- 簡報者檢視（M1）：分享者看到自己的分享縮圖與其他人的小格，不會變成滿版自己的螢幕。H5：縮圖在「你正在分享畫面」條的左端（96 × 54，每秒一張，從本機擷取、不經 SFU）；分享整個螢幕時不放縮圖，只寫原因。
- 手機（M1）：`getDisplayMedia` 不存在時隱藏分享按鈕，說明「手機瀏覽器不支援分享；可用電腦加入」。
- M2：分享格雙擊全螢幕；滑鼠滾輪／雙指縮放分享畫面；`useShareGeometry()` 回傳分享畫面在螢幕上的實際矩形（給 E7 標註對齊）。

### 非功能

- 開始分享到其他人看到第一幀 < 2 秒。
- 文字模式下 1080p 文件可讀（接收端不模糊）。

## 設計方向

- 分享就是 E2 的另一種 `publish({kind: 'screen'})`，不另外開連線。
- 版面規則在 E4 的 `layout.ts`：有 `screen` 軌時主區放分享、側列放人；多人分享時主區放「選中的」分享。
- 文字／動態模式只是 `applyConstraints` 與 `contentHint` 的組合，放 `src/media/share.ts`。

## 驗收條件

- [ ] AC-3.1 — 一人可分享螢幕／視窗／分頁，其他人在 2 秒內看到；版面自動切成分享為主；分享格有名字標籤。
- [ ] AC-3.2 — 分頁或系統音訊（瀏覽器支援時）作為獨立軌送出並在接收端播放；分享者可關掉分享音訊；不支援的瀏覽器不顯示該選項。
- [ ] AC-3.3 — 分享者看到「你正在分享」條；工具列、提示條、瀏覽器原生停止三條路停止都正確收尾並恢復版面；第二人按分享會問是否接手（M0；H5 起改成多人同時分享，不再問，見 AC-3.5）。分享到會議室本身時看到提醒與「換一個畫面」（H5）。
- [ ] AC-3.4 — 文字／動態模式可切換；文字模式 1080p 文件在接收端可讀；分享者在動態內容時收到切換提示。
- [ ] AC-3.5 — 多人同時分享；觀看者可選擇主區看誰；主持人可停止任何人的分享（E1 AC-1.4）。
- [ ] AC-3.6 — 分享者的版面是簡報者檢視（縮圖＋人），不會滿版自己的螢幕；手機沒有分享能力時隱藏按鈕並說明。

## 風險與對策

| 風險 | 對策 |
| --- | --- |
| Safari 分享沒有音訊、Firefox 系統音訊不穩 | 能力偵測後隱藏選項；`BROWSER-SUPPORT.md` 記錄 |
| 分享 4K 螢幕流量太大 | 文字模式限制 1080p／5 fps；simulcast 兩層（E2） |
| 分享者誤分享會議分頁造成無限鏡像 | `selfBrowserSurface: 'exclude'` ＋ 偵測提示 |

## 未決問題

- [x] **Q:** 文字模式預設幀率 5 fps 夠不夠（捲動文件時）？
      **A:** 不夠。D1 實測（#21）15 fps 捲動就卡，所以文字模式最高 30 fps、`balanced`；靜止的文件幾乎不花頻寬（H5 本機量測：1080p 靜止文件約 60–75 kbps），頻寬不夠時編碼器先降幀率、守住 1080p（1 Mbps 下約 10–23 fps）。數字在 ADR-001「分享模式與多人分享」。
