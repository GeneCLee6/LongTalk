## 背景

朋友會不會繼續用，取決於介面是否「像 Zoom 一樣不用學」。所以 E4 的策略是：**版面與工具列的心智模型照 Zoom**（底部工具列、格狀／演講者、右側聊天與參與者面板），視覺上走自己的風格（設計規格 `docs/DESIGN.md`，視覺稿 `docs/design/mockup.html`）。

三個畫面：首頁（建房／加入）、預先加入（名字、裝置、預覽）、會議室（主區、側欄、工具列）。手機是一等公民，不是縮小版。

## 目標

- M0：三個畫面可用；格狀版面 1–8 格自動排列；有分享時主區＋側列；誰在講話有外框；深淺色跟隨系統；手機直式可用。
- M1：預先加入完整版（音量表、喇叭測試）、演講者版面、釘選、聚光燈、PWA、快捷鍵、無障礙、繁中／英文、音效、視覺回歸測試、品牌定稿。

## 非目標

- 媒體邏輯（E2）、分享邏輯（E3）、聊天內容（E5）、品質設定的實作（E6）。
- 原生 App。

## 需求

### 功能

- **首頁**：標誌、一句話（「開著就不會斷的會議室」）、「開一間房」主按鈕、「輸入房間連結或代碼加入」、登入（M1）。首頁 JS gzip ≤ 150 kB。
- **預先加入**：名字（記住）、鏡頭預覽（鏡像）、麥克風音量表、裝置下拉三個、喇叭測試音（M1）、進房時是否開麥／開鏡頭；「加入」按鈕。等候室狀態也在這一頁（E1）。
- **會議室**：
  - 主區：格狀（1–8 格，依寬高比自動排；M2 分頁至 16 格）、演講者（講話者大格＋底部列）、分享（分享主區＋側列）；釘選與聚光燈覆寫自動選擇。
  - 名牌：名字、靜音圖示、訊號格（E2）、舉手（E5）、講話外框（音量門檻 ＋ 300 ms 防抖）。
  - 底部工具列：麥克風（含裝置選單）、鏡頭（含裝置選單）、分享、反應／舉手、聊天（未讀數）、參與者（人數）、更多（設定、統計、錄影、版面）、離開（紅）。
  - 右側欄：聊天、參與者，可收合；手機改為全屏抽屜。
  - 頂部：房間名、時間、連結複製、錄影紅燈（E8）、「重新連線中」條。
  - 離開後：「已離開」畫面，一題評分（1–5）、重新加入、回首頁。
- **手機**：直式單欄；一次顯示 4 格、其餘左右滑；工具列單手可及；橫式自動切成演講者；鎖螢幕仍能聽（Android；iOS 受限記在支援矩陣）。
- **PWA**：manifest、service worker（只快取殼，不快取 API）、安裝提示、全螢幕。
- **快捷鍵**：M 靜音、V 鏡頭、S 分享、C 聊天、P 參與者、R 舉手、空白鍵按住說話、Esc 關面板；可在設定看清單。
- **無障礙**：全部可鍵盤；焦點可見；名牌有 `aria-label`（「<名字>，已靜音，訊號好」）；狀態不只靠顏色；字幕區保留位置（E8）。
- **語言與主題**：繁體中文（預設）、English；跟隨系統深淺色，可手動切；介面文字只來自 `strings.ts`，顏色只來自 `tokens.ts`。
- **音效**：進房、離房、舉手、聊天（可關）。
- **品牌**：名稱、標誌（`docs/design/logo/`）、favicon、PWA icon、OG image。

### 非功能

- 會議室頁 JS gzip ≤ 350 kB（白板、模糊、錄影 lazy）。
- 8 格手機 CPU ≤ 60%（靠 E2 選層）；版面重算不掉幀（`ResizeObserver` ＋ CSS grid，不用 JS 逐格定位）。
- Playwright 視覺回歸：三個畫面 × 深淺 × 桌機／手機。

## 設計方向

- `src/ui/layout.ts`：純函式，輸入（成員數、分享數、釘選、聚光燈、容器尺寸、模式）輸出每格位置；有單元測試。
- `tokens.ts` 色票：主色「LongTalk 藍綠」（見 `DESIGN.md`）；深色為會議室預設（視訊畫面在深底上好看），淺色給首頁與設定。
- 元件：`Tile`、`Nameplate`、`Toolbar`、`SidePanel`、`TopBar`、`PreJoin`、`Home`、`Left`。
- 講話外框用 Web Audio `AnalyserNode` 在本機算自己的，別人的由 E2 的 audio level 統計。

## 風險與對策

| 風險 | 對策 |
| --- | --- |
| 版面在各種寬高比下破版 | `layout.ts` 純函式測試覆蓋 1–8 人 × 五種容器比例；視覺回歸 |
