## 背景

使用者點名的第二個差異化功能。**瀏覽器做不到控制別人的電腦**，所以被控端一定要裝一個桌面程式；我們的設計是：只有被控端裝「桌面端代理」（Tauri，體積小、跨平台），控制端仍在瀏覽器。代理連進同一個 RoomDO，發布螢幕軌（取代瀏覽器分享），接收控制端送來的滑鼠鍵盤事件。

這是整個產品**風險最高**的功能（安全、責任），所以排在 M3，而且動工前先寫威脅模型與功能 PRD `docs/PRD/f-remote-control-security.md`。

## 目標

- 被控端安裝代理、輸入房間與配對碼即可加入；控制端在瀏覽器請求控制；被控端每次都要按同意；控制期間全員看得到；被控端隨時中斷。
- Windows 與 macOS 可用；Linux 盡力。

## 非目標

- 無人值守存取（沒有人在被控端按同意就能連）——**永遠不做**。
- 檔案傳輸、遠端列印、喚醒。
- 手機被控。

## 需求

- 代理（Tauri ＋ Rust）：登入房間（連結或代碼 ＋ 一次性配對碼）、顯示在房間成員列表為「<名字> 的電腦」；擷取螢幕（多螢幕可選）發布到 SFU；系統托盤顯示狀態；Esc 連按三下或托盤「中斷」立即停止。
- 同意：控制端按「請求控制」→ RoomDO 建立請求（60 秒到期）→ 代理彈出系統層級對話框（名字、房間、「允許 10 分鐘／允許直到我中斷／拒絕」）→ 同意後全員收到提示並在被控端螢幕格顯示「<名字> 正在控制」。
- 控制事件：滑鼠移動（正規化座標）、點擊、滾輪、鍵盤（含組合鍵、輸入法以文字事件傳）；速率上限 120 事件／秒。
  - 原規劃（保留對照）：~~透過 DataChannel（低延遲）或 WebSocket 後備；每則事件帶房間 session 簽章與序號~~。
  - **N1 決定**（[`f-remote-control-security.md`](f-remote-control-security.md) §5.5）：先經 RoomDO 的 WebSocket 轉送，RoomDO 逐批檢查「是不是持有授權的那條連線」＋序號＋速率，不做逐則簽章（在這條路上簽章擋不了任何多出來的人，見該文件 Q2）；DataChannel＋每授權 HMAC 金鑰只在 N4 實測延遲不過時才做。
- 安全：代理只接受 RoomDO 轉發、授權 id 與序號對得上的事件（原規劃寫「簽章有效」，見上一條與 f-doc Q2）；控制權有時限；被控端畫面有持續的紅框與浮動「中斷」按鈕；代理日誌記錄每次控制的開始／結束／來源；敏感操作（例如系統對話框）不特別阻擋但有提示。
- 多平台：Windows（UIPI 限制說明）、macOS（螢幕錄製與輔助使用權限引導）、Linux（X11 可用、Wayland 盡力）。
- 剪貼簿同步（選用）、多螢幕切換。

## 設計方向

- `agent/`（Tauri）：Rust 端用 `enigo`／`rdev` 類注入、`scrap`／平台 API 擷取；前端 UI 很薄。
- 控制事件協定放 `shared/control.ts`；RoomDO 只做驗證、轉發與時限。
- **威脅模型與安全設計：[`f-remote-control-security.md`](f-remote-control-security.md)**（N1 定稿）。重點：每次控制都要被控端在系統對話框同意、授權綁控制端的連線、控制事件先經 RoomDO 的 WebSocket 轉送（不走 DataChannel，延遲預算見該文件 §5.5）、代理不聽任何埠且只連正式網域。
- 控制端的瀏覽器把分享格的滑鼠事件換算成 0–1 座標送出（複用 E7 的座標映射）。
